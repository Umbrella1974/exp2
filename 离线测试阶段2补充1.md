五、事件标注策略
============================================================

1. events.csv 中已有事件

   - slip_active false -> true: slip_start
   - slip_active true -> false: slip_end

补充约束：

1. 输出路径规则：
   analysis_summary.json 固定写到 session_dir/analysis_summary.json。
   图像默认写到 session_dir/plots/。
   如果提供 --out-dir，只改变图像输出目录，不改变 analysis_summary.json 的位置。
   --overwrite 只允许覆盖 analysis_summary.json 和本脚本生成的 PNG，不得删除或覆盖 session 原始记录文件。

2. time-column fallback：
   优先使用用户指定的 --time-column。
   如果该列缺失或全为空，按 sample_time -> trial_time -> raw_timestamp -> frame_index 的顺序 fallback。
   如果使用 frame_index 作为横轴，必须在 warnings 中记录。

3. 事件合并：
   事件来源包括 events.csv recorded events 和 processed_frames.csv derived events。
   内部保留 source = recorded / derived。
   如果同一 frame_index 或近似同一 time 已经存在同类型 recorded event，不要重复加入 derived event。
   derived events 只用于 analysis_summary 和 plot，不写回 events.csv。

4. haptic active 定义：
   优先从 haptic.csv 判断。
   haptic_state 非空且不属于 "", "none", "NONE", "off", "OFF", "false", "False", "0" 时视为 active。
   如果 haptic_state 为空但 command_type 非空，也可视为 active。
   haptic_event_count 统计 haptic active 的 false->true 边缘次数。
   如果 haptic.csv 缺失，则 fallback 到 processed_frames.csv 的 haptic_state，并写 warning。

5. blocked_frame_count 统计口径：
   优先统计 blocked_force_active == true。
   如果该列缺失或全为空，再 fallback 到 stop_reason / block_motion_state / contact_state 中包含 "BLOCKED" 的帧。
   fallback 行为写入 warnings。

6. track bounds best-effort：
   trajectory_track_map 尝试从 trial_config 中读取：
   - track_bounds_task
   - track_bounds
   - track_region
   - bounds
   - scene_auto.track_bounds
   - scene_auto.track_bounds_task
   如果无法识别，不要失败，只跳过 track/corridor 边界绘制，并写 warning。

7. trajectory event points：
   轨迹图中的 blocked/slip/haptic 事件点坐标从 processed_frames.csv 获取。
   如果事件有 frame_index，优先使用对应帧。
   如果只有 time，则使用最近 time 的 processed frame。
   如果找不到对应帧，跳过该事件点并写 warning。

8. matplotlib 测试：
   tests/test_analyze_session.py 中不要依赖环境是否安装 matplotlib。
   需要测试 matplotlib unavailable 时，用 monkeypatch 或内部 flag 模拟。
