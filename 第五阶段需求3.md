一、新增 calibration_live_runner.py
============================================================

新增模块：
calibration_live_runner.py

职责：
封装 live calibration 采样流程，既能用真实 live stream，也能用 raw JSONL simulated stream。

核心数据结构：

1. CalibrationSegmentSpec
字段：
- label: str
  取值：
  - origin
  - long_axis_line
  - width_axis_line
  - diagonal_line
- prompt: str
- duration_seconds: float
- min_samples: int
- segment_type: "static_point" | "line"

2. CalibrationLiveConfig
字段：
- calibration_id: str
- point_source: "tracker_position_world" | "pinch_center_world"
- sample_duration_seconds: float，默认 5.0
- min_samples: int，默认 10
- min_line_length: float，默认 0.10
- up_hint: list[float]，默认 [0,0,1]
- timestamp_scale: float，默认 0.001
- output_path: Path
- notes: str | None
- require_enter_between_segments: bool，默认 true
- auto_advance: bool，默认 false

3. CalibrationLiveResult
字段：
- calibration
- segment_summaries
- warnings
- errors
- live_metrics_summary

核心函数：

- collect_calibration_segment(frame_iter, segment_spec, config) -> dict
- run_live_table_calibration(frame_iter, config) -> CalibrationLiveResult

frame_iter 输入应产出 raw frame 或 LiveRawFrame。
每帧处理：
1. raw frame -> parse_raw_manus_vive_frame
2. DeviceFrame -> ManusViveExperimentAdapter -> ExperimentInputSample
3. calibration_sampling.extract_calibration_point_from_sample
4. 收集有效点
5. 记录 segment metrics

segment metrics 至少包括：
- label
- start_monotonic_time
- end_monotonic_time
- duration_seconds
- received_frame_count
- valid_sample_count
- invalid_sample_count
- tracker_valid_count
- hand_valid_count
- point_source
- warnings

采样规则：
- origin 是 static_point，用 summarize_static_points
- long / width / diagonal 是 line，用 fit_line_3d
- 所有 line 点合并做 plane fit
- 最终构造 FormalCalibration
- validate_calibration
- validation errors 阻止保存
- validation warnings 打印并写入 calibration.warnings

注意：
不要在这里启动 TrialController。
不要在这里创建 block/map。
这是 calibration-only runner。

三、新增 live_calibrate_table.py
============================================================

新增脚本：
live_calibrate_table.py

目标：
命令行版桌面三线在线 calibration 工具。

输入参数：

输出与基本配置：
- --out path，默认 data/calibration/live_table_calibration.json
- --calibration-id 可选
- --notes 可选
- --point-source tracker_position_world / pinch_center_world，默认 tracker_position_world
- --sample-duration-seconds 默认 5.0
- --min-samples 默认 10
- --min-line-length 默认 0.10
- --up-hint 默认 "0,0,1"
- --timestamp-scale 默认 0.001

输入源模式，二选一：
1. simulated raw JSONL:
   - --raw-jsonl path
   - --simulate-live，布尔
   - --replay-real-time，布尔，默认 false
   - --speed 默认 1.0
   - --max-frames 可选

2. live TCP stream:
   - --live-host 默认 127.0.0.1
   - --live-port 默认 8888
   - --use-live-stream，布尔

互斥规则：
- --raw-jsonl 和 --use-live-stream 至少选一个
- --raw-jsonl simulated mode 不需要真实设备
- --use-live-stream 使用 live_raw_stream.py 的 LiveRawStreamServer

交互参数：
- --auto-advance，布尔，默认 false
  如果 true，每段采样完成后自动进入下一段，方便测试
- --no-confirm-save，布尔，默认 false
  如果 true，有 warning 也直接保存；主要用于测试
- --print-every 默认 30

交互流程：
1. 打印说明：
   - 小桌子标定
   - origin 静止 5 秒
   - long line 5 秒
   - width line 5 秒
   - diagonal line 5 秒
2. 对每个 segment：
   - 如果 auto_advance=false，提示用户按 Enter 开始
   - segment 采样期间打印进度：
     - elapsed seconds
     - valid samples
     - tracker_valid / hand_valid
   - 采样完成后打印 segment summary
3. 四段完成后：
   - 计算 FormalCalibration
   - 打印 quality summary
   - 如果 errors：失败，不保存
   - 如果 warnings：
     - 如果 no_confirm_save=false，询问是否保存
     - 如果 no_confirm_save=true，直接保存
4. 保存 calibration.json

metadata 中必须写：
- calibration_type = formal_table_lines
- is_formal_calibration = true
- collection_mode = "live_stream" 或 "raw_jsonl_simulated_live"
- point_source
- sample_duration_seconds
- warning:
  - simulated mode: "This calibration was collected from raw JSONL simulated live mode; use live stream for formal subject calibration."
  - live mode: "This calibration was collected from live stream."

============================================================
六、README
============================================================

README 增加 Stage 5B-1 说明：

1. live_calibrate_table.py 是命令行版 live calibration runner。
2. 它支持两种输入：
   - raw JSONL simulated live
   - live TCP stream
3. 当前推荐先用 simulated live 测完整流程，等设备空闲再接 live stream。
4. 它不启动 TrialController，不做正式实验，只生成 calibration.json。

示例 1：无设备，用 raw JSONL 模拟 live calibration：

python live_calibrate_table.py \
  --raw-jsonl path/to/raw_frames.jsonl \
  --simulate-live \
  --auto-advance \
  --no-confirm-save \
  --out data/calibration/simulated_live_table_calibration.json

示例 2：真实 stream：

python live_calibrate_table.py \
  --use-live-stream \
  --live-host 127.0.0.1 \
  --live-port 8888 \
  --out data/calibration/live_table_calibration.json

然后启动 manus_vive_com 发送数据到 127.0.0.1:8888。

同意你的三个实现口径，请按下面方式实现：

1. raw JSONL simulated live mode 默认按文件流顺序划分四段：
   - 前 sample_duration_seconds：origin
   - 接着 sample_duration_seconds：long_axis_line
   - 接着 sample_duration_seconds：width_axis_line
   - 接着 sample_duration_seconds：diagonal_line

   这要求 raw JSONL 本身已经按这个动作顺序录制。
   如果用户想从任意帧段截取，应继续使用 calibrate_from_raw_jsonl_table.py，而不是 live_calibrate_table.py。

2. simulated live 模式下，segment duration 必须使用 frame_time / raw timestamp / sample_time 判断。
   如果 --replay-real-time=false，也不能用 time.monotonic() 切段。
   真实 live stream 模式才用 time.monotonic() 计时。

3. 如果 raw timestamp 不可用或不能形成单调 frame_time，应清晰失败，提示用户使用 calibrate_from_raw_jsonl_table.py 或提供 timestamp_scale / sample-window-frame 方案。
   第一版不要再给 live_calibrate_table.py 增加 --origin-start-frame 等离线截段参数，避免和 calibrate_from_raw_jsonl_table.py 职责重叠。

4. 真实 live stream 模式下，每段开始采样前清空当前 queue，避免 Enter 前积压的旧帧混入当前 segment。
   summary / calibration metadata 中记录 queue_cleared_before_segment = true。

其他按原 Stage 5B-1 prompt 实现。
