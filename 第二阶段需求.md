二、新增模块 1：task_coordinate_system.py
============================================================

实现 TaskCoordinateSystem，用于把世界坐标转换到任务坐标。

背景：
实验中不依赖 SteamVR / Vive 的绝对 room setup。
每次实验或每组 trial 需要定义一个自己的任务坐标系：
- origin_world：任务原点
- x_axis_world：由被试水平移动方向定义
- z_axis_world：竖直方向，来自配置，例如 [0, 1, 0]
- y_axis_world：由 z_axis × x_axis 得到，构成右手系

要求实现：

class TaskCoordinateSystem:
    origin_world
    x_axis_world
    y_axis_world
    z_axis_world

    world_to_task(p_world) -> np.ndarray shape (3,)
    task_to_world(p_task) -> np.ndarray shape (3,)
    vector_world_to_task(v_world) -> np.ndarray shape (3,)
    vector_task_to_world(v_task) -> np.ndarray shape (3,)

构造函数 / factory：

build_from_origin_and_x_point(
    origin_world,
    x_point_world,
    up_axis_world,
    min_x_axis_length=0.1
) -> TaskCoordinateSystem

规则：
1. x_axis 应该由 x_point_world - origin_world 得到。
2. 需要把 x_raw 投影到垂直于 up_axis_world 的水平面上。
3. 如果投影后长度小于 min_x_axis_length，抛出 ValueError。
4. z_axis = normalize(up_axis_world)。
5. y_axis = normalize(cross(z_axis, x_axis))。
6. 为避免数值误差，重新正交化 x_axis = normalize(cross(y_axis, z_axis))。
7. 保证 x/y/z 是单位向量。
8. 保证 x × y ≈ z。
9. 不要依赖任何 SDK。

测试：
- origin 转换后是 [0,0,0]。
- 沿 x_axis_world 移动 1m 后 task 坐标 x≈1。
- 沿 y_axis_world 移动 1m 后 task 坐标 y≈1。
- 沿 z_axis_world 移动 1m 后 task 坐标 z≈1。
- task_to_world(world_to_task(p)) ≈ p。
- x_point 太近时抛出 ValueError。
- x_raw 含有竖直分量时，能正确投影到水平面。

三、新增模块 2：trial_controller.py
============================================================

实现 TrialController。它只管理实验生命周期，不管理木块几何细节。

TrialController 不应该知道轨道 clamp 怎么做，也不应该直接判断 blocked surface。
它只负责：
- trial 是否开始
- prompt_on 时间
- running 状态
- subject_end
- timeout
- detach_count 超限
- 每帧调用 BlockController
- 收集 FrameOutput / EventRecord

TrialState enum：

WAITING
PROMPT
RUNNING
ENDED_BY_SUBJECT
FAILED_TIMEOUT
FAILED_TOO_MANY_DETACHES
TRACKING_INVALID

状态语义：

1. WAITING
   - trial 尚未开始。
   - 不记录正式实验数据，或者只记录 debug 数据。
   - 收到 start_trial() 后进入 PROMPT。

2. PROMPT
   - 试次提示已经出现。
   - 记录 prompt_on event。
   - prompt_on_time = current_time。
   - 下一帧或调用 begin_running() 后进入 RUNNING。
   - 第一版可以让 start_trial() 直接进入 RUNNING，但必须记录 prompt_on。

3. RUNNING
   - 正式记录中。
   - 每帧把输入转换为 BlockController 的 FrameInput。
   - 调用 BlockController.update()。
   - 检查失败条件：
     a. time_since_prompt > trial_timeout_seconds -> FAILED_TIMEOUT
     b. total_detach_count > max_detach_count -> FAILED_TOO_MANY_DETACHES
   - 如果 subject_end=True -> ENDED_BY_SUBJECT。

4. ENDED_BY_SUBJECT
   - 受试者主动结束 trial。
   - 正常结束，不等于 success。
   - 暂时不设 trial_success。
   - 记录 subject_end event。

5. FAILED_TIMEOUT
   - 超时失败。
   - 从 prompt_on 开始计时。

6. FAILED_TOO_MANY_DETACHES
   - active_release_count + forced_detach_count + unexpected_detach_count 超过 max_detach_count。
   - 记录 too_many_detaches event。

7. TRACKING_INVALID
   - 如果 running 中连续 tracking_invalid，可暂时进入此状态或只记录 invalid event。
   - 第一版建议不要让 TRACKING_INVALID 终止 trial。
   - 只记录 tracking_invalid event，并让 BlockController 处理 tracking invalid。
   - 如果你实现 TrialState.TRACKING_INVALID，需要能在 tracking 恢复后回到 RUNNING。

TrialController API 建议：

class TrialController:
    def __init__(
        self,
        block_controller,
        task_coordinate_system,
        config,
        recorder=None,
    )

    def start_trial(self, time: float, trial_id: int) -> None
    def update(self, sample: ExperimentInputSample) -> TrialFrameResult
    def end_by_subject(self, time: float) -> None
    def reset(self) -> None

ExperimentInputSample:
- time
- pinch_center_world 或 pinch_center_task
- pinch_distance
- tracker_valid
- subject_end=False
- metadata 可选

如果输入是 world 坐标：
- TrialController 用 TaskCoordinateSystem 转换到 task 坐标。
如果输入已经是 task 坐标：
- 可绕过转换。
建议字段里明确 coordinate_space: "world" / "task"。

TrialFrameResult:
- trial_id
- trial_state
- frame_output from BlockController
- haptic_feedback_state
- events list
- time_since_prompt
- failure_reason optional

- pinch_insufficient
- block_moved
- block_blocked

第一版建议：
- frames.csv 记录 slip_active。
- events.csv 记录 slip_start / slip_end，避免每帧刷事件。

- time

- tracker_valid
